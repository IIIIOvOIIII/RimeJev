# Security and privacy

- No shared credentials are provided. The user-requested direct API-key mode stores the key in macOS Keychain through a hidden settings field, with no redisplay. Native reads/writes run off the main thread; the child receives a bounded one-shot stdin message, never a key in argv/env/settings. Existing user-authorized Vault-compatible helper/service metadata remains supported. Credential-source choice is explicit and failures never switch sources.
- Do not submit tokens, private keys, account cookies, personal dictionaries, typed text, settings, logs, or backups in issues, pull requests, release assets, or Git history.
- `work/`, `artifacts/`, `.venv/`, local settings, sockets, model weights, and dictionary databases are ignored. `.gitignore` is not a substitute for inspecting staged files and scanning history.
- Cloud and cloud + local modes send the current bounded context, pinyin, and candidates to TypeSafe. Global enhancement starts off. The user may enable cloud explicitly for a specific app or as the default for apps without overrides; explicit app-off choices remain off. Secure input and the input method’s own settings never run enhancement. Local mode never silently switches to cloud.
- Training capture is separately opt-in and off by default with an empty app list. Raw captures are AES-GCM encrypted locally with a distinct Keychain key; queue/path/quota/key failures pause collection. Capture never adds model calls. Preview/export/trash first disable collection and keep it off. Plaintext exports require explicit local action and must be reviewed before sharing. No capture file or export belongs in Git. Secure input and the IME's own settings are excluded; ordinary text secret-pattern filtering is heuristic, not a guarantee. See [training data](docs/TRAINING_CAPTURE.md).
- TLS verification and redirect rejection protect credential retrieval. Do not weaken these checks to work around configuration errors.
- This source release uses an ad-hoc local build, not Apple Developer ID notarization. macOS input-source consent remains required.

If you find a security issue, use GitHub's private vulnerability reporting when available, or contact the repository owner privately. Do not post a working secret or sensitive reproduction data in a public issue.

The direct-key implementation follows Apple’s [SecItem Keychain API guidance](https://developer.apple.com/documentation/security/using-the-keychain-to-manage-user-secrets) and uses an [NSSecureTextField](https://developer.apple.com/documentation/appkit/nssecuretextfield) for entry. UI success indicates storage, not proof that a provider accepts the key.
