# 中文拼音语境选词合成评估集

这是 Rime-Jev 的历史 0.2 合成评估集。新版 0.2.4 采用保留首选、推荐第二位的策略，不能直接把旧首选提升指标当作新版 UI 效果。全部样例由本次任务人工构造，使用公开常识性的词语、技术术语和虚构评估语境；没有读取、复制或接触私人词库、用户文本、输入记录或日志。因此，这个数据集只用于检查语境选词逻辑，不代表任何用户的真实输入行为，也不提供真实用户偏好或模型效果结论。

## 规模与隔离

| split | 同音组 | 样例数 | 用途 |
| --- | ---: | ---: | --- |
| `calibration` | `g001`–`g020` | 100 | 只用于校准阈值、候选窗口和展示策略 |
| `acceptance` | `g021`–`g060` | 200 | 独立验收集；冻结校准参数后使用 |
| 合计 | 60 | 300 | 每组 5 条 |

每个 `group` 的 5 条记录使用同一输入形式，并且整个组只属于一个 split。`g001`–`g020` 与 `g021`–`g060` 没有交集；本集的 60 个拼音输入也没有跨组重复，避免同音组或等价输入从 calibration 泄漏到 acceptance。`id` 分别连续编号为 `cal-001`–`cal-100` 和 `acc-001`–`acc-200`。

固定参考图样例在 `g001`：

- `context="汽车"`、`pinyin="youxiang"` 的正确词是 `油箱`。
- `context="我现在"`、`pinyin="youxiang"` 的正确词是 `又想`。

## JSONL 格式

`cases.jsonl` 每行是一个独立 JSON 对象，字段顺序保持为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 全集唯一的稳定 ID |
| `group` | string | 同音组 ID；每组正好 5 条 |
| `split` | string | `calibration` 或 `acceptance` |
| `context` | string | 当前连续输入前文；可以是空字符串，表示没有上下文 |
| `pinyin` | string | 不带声调的全拼、简拼，或明确的 ASCII 混输 token |
| `target` | string 或 null | 正确的中文词、专名或英文技术 token；没有可安全选择的词时为 `null` |
| `category` | string | 样例覆盖类型 |
| `reason` | string | 仅在 `target` 为 `null` 时出现，说明为什么应返回 `none` |

非空 `target` 不得原样出现在 `context` 中。`target=null` 的记录必须有非空 `reason`；`target` 有值的记录不带 `reason`。数据集不内嵌候选列表，因为候选覆盖率必须在同一冻结万象配置下单独取得，不能把某次本地候选结果伪装成金标准。

## 输入与拼音约定

- 普通中文输入使用小写、不带声调的全拼，例如 `youxiang`、`shijian`。
- `g041`–`g045` 使用首字母简拼，例如 `sjk` 可对应“数据库”“手机壳”“升级款”；简拼的正确性按目标词各音节首字母核对。
- `g046`–`g049` 和 `g052`–`g055` 是中英混输或英文技术 token，例如 `api` 对应 `API`，`http` 对应 `HTTP`。这些行保留英文目标的大写写法，`pinyin` 使用用户可能输入的 ASCII 小写形式。
- 词语的拼音按目标词的普通话读音核对；不同声调在本输入字段中按 Rime 常见的无调拼音合并。

覆盖类型包括普通同音词、技术名词、人名和其他专名、简拼、中英混输、长上下文、否定表述、候选排列扰动、无上下文以及 `none`。其中 `person_name_missing` 表示专名金标准必须保留，即使本地候选当轮没有召回；它不是对某个私人词库当前内容的声明。

## none 与候选缺失

`g050` 提供空 `context` 的无上下文样例，目标为空并带原因。`g051` 提供专名或地名可能未进入候选集合的样例，同样使用 `target=null` 和 `reason`。这些记录要求评估器在无法从当前候选安全确认目标时返回 `none`，不能把一个普通同音词误当成正确答案。

`none` 不是模型错误的同义词。报告中应将以下情形分开：

1. 当前本地候选包含 `target`，模型选择正确或错误。
2. 当前本地候选不包含非空 `target`，这是召回覆盖缺口，不应计作模型把已给候选选错。
3. `target=null` 且 `reason` 指明没有可安全确认的词，这是 `none` 适用样例。

## coverage 报告边界

评估器应先在不改变原始 JSONL 的情况下，为每个 `id` 记录冻结候选集合中的覆盖状态，再计算选择指标。建议的外部报告至少包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 对应本文件的样例 ID |
| `candidate_covered` | 非空 `target` 是否出现在本轮候选中 |
| `coverage_class` | `covered`、`missing` 或 `not_applicable`（`target=null`） |
| `selection_class` | `correct`、`wrong_choice`、`none_expected`、`not_evaluable` 等 |
| `candidate_count` | 本轮实际评分的候选数，包含或不包含 `none` 要明确记录 |

专名行（`person_name_missing`）的 `target` 仍是正确词；即使 `candidate_covered=false`，也要保留该 gold 并在 coverage 报告中标为 `missing`。本数据集没有运行万象、Jev、this-that-model 或任何其他模型，因此不预填 coverage、准确率、延迟、费用或改善百分比。

## 验证记录

本次生成后对目标文件做了只读检查：

- JSONL 可逐行解析，行数为 300；`calibration=100`、`acceptance=200`。
- `group` 共 60 个，每组正好 5 行；每组只属于一个 split，且组内拼音一致。
- `id` 唯一并覆盖两段连续 ID；非空目标共 290 条，空目标共 10 条，均有 `reason`。
- 对 290 条非空目标检查了目标词不出现在 `context` 中；没有发现泄漏。
- 用人工维护的全拼、简拼和混输对照逐行核对目标拼音；没有发现不匹配。没有安装或调用拼音包、联网服务或模型。

这些是数据完整性检查，不是模型测试结果。后续模型评估必须保存实际候选覆盖与运行指标，并继续保持 calibration 与 acceptance 的组级隔离。

## 集成审阅后的评分边界

无上下文和未知目标的十条控制样例使用 `scoring=retain_order_control`：不能将“意图未知”误写成“所有选项均不合适”，不计入模型唯一答案正确率。无法凭语境确定具体姓名的 `person_name_missing` 仅报告覆盖率，标为 `coverage_only`。其余样例在评分时仍区分未召回、不可比较片段和有效候选。300 条是样例数量，不等于300条均可判定唯一答案。

离线 Rime 取样使用冻结词库副本和独立会话，保留万象配置，但不重演每个前文的历史按键。因此模型对前文的增益属于受控合成比较，最终仍需真实宿主应用验证。
